# 斐讯 R1 小智 —— 通用安装使用说明

> 适用于 release **V2.0.x** 系列（`XiaoZhi_Unisound_V2.0.x` / `XiaoZhi_EchoService_V2.0.x` / `XiaoZhi_SoHost_V2.0.x`）。
> 文中 `<音箱IP>` 指音箱局域网地址（如 `192.168.2.5`），`<NAS IP>` 指部署 Docker 服务的机器地址（如 `192.168.2.189`）。

**总览：整套方案 4 个部件**

| 部件 | 跑在哪 | 端口 | 作用 |
|---|---|---|---|
| R1 小智客户端（3 个 APK） | 音箱 | 8080（Web 控制台） | 顶替原厂云语音，接小智服务端，保留原厂四麦 AEC |
| **R1XiaoZhi_MediaServer**（Docker） | NAS / 任意 Docker 机 | 8100 | 小智曲库：本地音乐 + 在线音乐 + 网络电台，一个地址全包 |
| **落雪 lxserver**（Docker） | NAS / 任意 Docker 机 | 9527 | 在线取链通道（搜索/取播放链接都走它） |
| 小智服务端 | 官方 或 自建 | 8003(OTA) / 8000(WS) | 语音大脑；官方即 `api.tenclass.net`，自建即 xiaozhi-esp32-server |

```
音箱(R1) ──8080 Web控制台── 电脑浏览器
   │
   ├─ 语音 WS ── 小智服务端（官方 / 自建）
   │
   └─ 音源 http://<NAS IP>:8100/index.json
              └── MediaServer ── 落雪 lxserver:9527 ── 各音乐平台
```

---

## §1 前置条件

1. **音箱固件必须是 3448**。其它版本不要装（安装脚本会自己校验并拒绝）。
   查看方法：`adb shell getprop ro.build.version.incremental`；不是 3448 先用原厂工具刷机。
2. 音箱与电脑 / NAS 在**同一局域网**，WiFi adb 可连（`192.168.2.5:5555` 这种形式）。
3. 一台能跑 Docker 的机器（群晖 Container Manager、飞牛、PVE 里的 Linux、x86 小主机都行）。
4. （可选）自建小智服务端：xiaozhi-esp32-server 等；不想自建就直连官方。

## §2 安装音箱端 APK

### 2.1 一键安装（推荐）

把整个发布目录拷到 Windows 电脑，**双击 `一键安装.bat`**（用 CMD/资源管理器，不要用 Git Bash）：

1. 提示输入音箱 IP，直接回车用默认 `192.168.2.5:5555`（USB 线则输 `usb`）。
2. 连上后选菜单 **`[1] 一键安装`**：自动传 3 个包 → 逐字节核对 → 安装 → 拉起服务 → 等 Web 控制台就绪。
3. 看到 3 次 `Success` +「装机完成」即可，全程约 2 分钟（WiFi 传 32MB 主包约 100 秒）。

### 2.2 手工安装（不想用脚本）

CMD / PowerShell 下：

```bat
adb connect 192.168.2.5:5555

adb push apps\XiaoZhi_SoHost_V2.0.x.apk     /data/local/tmp/sohost.apk
adb push apps\XiaoZhi_Unisound_V2.0.x.apk    /data/local/tmp/jp2.apk
adb push apps\XiaoZhi_EchoService_V2.0.x.apk /data/local/tmp/echo.apk

adb shell /system/bin/pm install -r -d /data/local/tmp/sohost.apk
adb shell /system/bin/pm install -r -d /data/local/tmp/jp2.apk
adb shell /system/bin/pm install -r -d /data/local/tmp/echo.apk

adb shell am startservice -n com.phicomm.speaker.device/.ui.service.WindowsService
adb shell am startservice -n com.phicomm.speaker.player/.EchoService
```

**三个包都要装**，缺 so 宿主（SoHost）语音上行编码就是废的。装完浏览器先别急着开 `:8080`，
等 15~40 秒（首次装机要从 apk 里抠 Opus 库、初始化四麦，慢一点是正常的）。

### 2.3 验证

- 浏览器打开 `http://<音箱IP>:8080/`，页脚能看到版本号（`2.0.x` / `pl-2.0.x`）。
- 对音箱喊唤醒词：**「小智小智」**（产线固件里也保留着「小讯小讯」，都能用）。

## §3 安装落雪 lxserver（Docker）—— 在线取链通道

> R1 在线歌不是自己爬源，而是**把取链整体中继给落雪**。落雪没部署 = 在线歌播不了
> （本地曲库和电台不受影响）。

### 3.1 起容器

docker-compose（推荐）：

```yaml
services:
  lxserver:
    image: xcq0607/lxserver:latest
    container_name: lxserver
    restart: unless-stopped
    ports:
      - "9527:9527"
    volumes:
      - ./data:/server/data
      - ./logs:/server/logs
      - ./cache:/server/cache
    environment:
      - TZ=Asia/Shanghai
```

```bash
docker compose up -d
```

或单条命令：

```bash
docker run -d -p 9527:9527 \
  -v $(pwd)/lxdata:/server/data -v $(pwd)/lxlogs:/server/logs -v $(pwd)/lxcache:/server/cache \
  --name lx-sync-server --restart unless-stopped xcq0607/lxserver:latest
```

### 3.2 装完必做

1. 打开 `http://<NAS IP>:9527/admin` → 系统配置 → **改掉默认管理员密码（`123456`）**。
2. 有自定义音源（订阅源）的，在后台按落雪 desktop 同样的方式配进去 —— 服务端跑的就是
   落雪原版 `musicSdk`，手机上用什么源这里就认什么源。

## §4 安装 R1XiaoZhi_MediaServer（Docker）—— 小智曲库

一个容器一个端口（**8100**）解决全部音源：本地音乐库 + 在线音乐库 + 网络电台。
对外只有一个地址：`http://<NAS IP>:8100/index.json`。

1. 把发布目录里的 **`R1XiaoZhi_MediaServer/`** 整个拷到 NAS，例如
   `/volume1/docker/R1XiaoZhi_MediaServer`。
2. 编辑 `docker-compose.yml`，把音乐目录改成你自己的：

   ```yaml
   - /volume1/music:/music     # 冒号左边 = NAS 上你的音乐目录
   ```
3. 起容器：

   ```bash
   cd /volume1/docker/R1XiaoZhi_MediaServer
   docker compose up -d --build
   ```

4. 浏览器打开 `http://<NAS IP>:8100` → **音源** 页：
   - **落雪 docker（lxserver）**：填 `http://<NAS IP>:9527` → 保存（会自动连通自检）。
     具名用户再填「用户名 + Token」（落雪后台建的持久化 API Token）；用 open 公开用户就都留空。
   - 三块开关（本地 / 在线 / 电台）：关掉哪块，R1 那边立刻「没有」，不用重启。
   - 默认音质：`128k`（默认，最稳最快）/ `192k` / `320k`。

> `files/` 是挂载卷（音源配置、在线池、标签缓存、电台清单），**重建容器不丢**。
> 首次扫 1000+ 首本地歌要等一会儿，扫完自动缓存秒回；往 NAS 传了新歌就在 Web 点 `/reindex`。

## §5 各端配置（装完照这张表对一遍）

### 5.1 音箱控制台 `http://<音箱IP>:8080`

| 位置 | 配什么 | 说明 |
|---|---|---|
| 设置 → **小智服务器** | OTA 地址 | **留空 = 官方**；自建填 `http://<服务端IP>:8003/xiaozhi/ota/` |
| | WS 地址 | **留空 = 由 OTA 地址自动获取**（推荐，官方/自建都对）；特殊需要才手填 `ws://...:8000/xiaozhi/v1/` |
| | Token | **留空 = 由 OTA 下发**（官方下发的是 `test-token`）；自建有鉴权才填 |
| | 生效中 ws / 生效中 token | 只读展示，显示的是**当前真实生效值**，用来核对配置有没有吃上 |
| 设置 → **音乐源** | 只留一行 `http://<NAS IP>:8100/index.json` | 保存后点「重载」让小智重新拉曲库索引 |
| 设置 → **本地曲目数量** | `0` = **不限制**（全库） | 设 0 保存后不会跳回 500；显示的生效值 5000 即不限 |
| 音乐 → 收藏 | 见 §6 | 上传 / 备份 / 重链接都在这页 |

### 5.2 NAS（8100）与落雪（9527）

| 端 | 必配项 | 备注 |
|---|---|---|
| MediaServer 8100 音源页 | 落雪地址 | 不填在线歌全灭 |
| lxserver 9527 | 管理密码、订阅源 | 密码务必改 |

### 5.3 检查清单（从下往上验）

```bash
# 1) 曲库服务活着没
curl http://<NAS IP>:8100/api/health
# 2) 落雪通不通（搜索一条）
curl "http://<NAS IP>:9527/api/music/search?name=晴天&limit=5"
# 3) 音箱能不能拿到曲库（音箱上直接跑）
adb shell "sh -c 'curl -s http://<NAS IP>:8100/index.json | head -c 300'"
```

## §6 小智功能激活

### 6.1 两种「激活」别搞混

| 名字 | 要不要做 |
|---|---|
| 原厂「小讯激活 / 绑定音箱」 | **不需要**。原厂云已停服，本包已在 smali 层把「未绑定/无网络/待升级」三道唤醒闸门拆掉，恒为已激活 |
| **小智激活码**（连服务端） | **第一次连服务端必须做** |

### 6.2 激活步骤（连官方或自建都一样）

1. 浏览器打开 `http://<音箱IP>:8080/`，顶部「激活」卡片显示 **6 位激活码**。
2. 把激活码填到小智服务端的设备绑定页面（官方网页 或 自建服务端的管理页）。
3. 绑定成功后卡片状态变绿；之后正常唤醒对话即可。
4. **重装 APK 会清空 OTA 地址** —— 重装后要重新在「设置 → 小智服务器」里填一遍
   （或确认留空走官方），并重新走一次激活。

> 激活不成功先看「设置 → 生效中 ws 地址」是不是你想要的那个；WS 连不上一切免谈。

## §7 自定义歌单（收藏）：写法、上传、备份

收藏列表就是 R1 的自定义歌单，**主本在音箱内** `files/r1_fav.json`，**上限 5000 条且导入不限制数量**。

### 7.1 txt 写法（上传歌单用）

在控制台 `http://<音箱IP>:8080` → **音乐 → 收藏** 页 →「上传歌单」，选一个 UTF-8 的 txt，每行一首，两种写法：

```
歌名 - 歌手
```

或富格式（4 段竖线分隔；想直接给地址/专辑/时长就用它）：

```
歌名|歌手|地址|专辑|时长
```

- `地址` 可空（空 = 到播的时候再在线搜）；给了 `http(s)://` 地址就直接按地址播。
- 歌名本身含 ` - ` 的（如《Rain - 雨声》）必须用富格式，否则会被拆错。
- **导入不限条数**（几千条也就几十秒，约 9ms/首），导入时只存歌名不联网，
  播到哪首才解析哪首。

### 7.2 上传 / 导入行为

- 上传 = **清空现有收藏再逐条导入**（整份替换，不是追加）。
- 同一首歌（歌名+歌手归一化后相同）只算一条，不会收重。
- 行尾带扩展列（§7.3 导出再导回）会把上次的**在线绑定**一起带回来，导完立刻能播、不用重新解析。

### 7.3 备份 / 搬家

收藏页「**导出歌单**」得到一份 txt，就是完整备份：

- 每行行尾带 `| src=... | rid=... | rt=... | ra=... | lt=... | la=...` 等绑定列（富格式导出）。
- 换机 / 重装 / 换 NAS，把这份 txt 重新上传即可**无损还原**（含在线源绑定）。
- 定期导一份存 NAS 就是备份；文件很小（千首级别也就几百 KB）。

### 7.4 日常维护（收藏页操作）

| 操作 | 怎么做 |
|---|---|
| 播放某一首 | 点行首播放键；**先查当前队列**，在队列里就原地播，不打断队列 |
| 删除一条 | 行尾 `✕`（会先弹确认） |
| **重新匹配**（配错了想换） | **长按歌名 0.5 秒** → 行变红 + 🔗 → 从在线结果里挑一版绑上去；绑成功立刻褪红 |
| 红色标记 | 表示这首上次没解析成功（内存态，重启即清）。绑好后自动褪红 |
| 显示名字 | 默认「有匹配名显示匹配名，没匹配显示自定义名」；设置页开了**「显示自定义歌曲名」**开关后只显示你导入时的原名（播放队列同样生效） |

## §8 语音控制（MCP）全表

R1 已绑定到小智服务端作为 MCP 端点，工具分三组：`self.r1player.*`（播放）、
`self.r1light.*`（灯）、`self.r1alarm.*`（闹钟）。

> 注意两点：
> - **自定义音乐库开关**（设置页）关掉后，工具表只剩灯控 + 闹钟；开了才有全套播放工具。
> - 服务端**只在连接握手时拉一次工具表** —— 改了开关后说一句「小智小智」重新唤醒
>   （或控制台点「重启小智」）让新表生效。

### 8.1 播放控制 `self.r1player.*`

| 语音示例 | 背后动作 |
|---|---|
| 「播放晴天」「我想听周杰伦的晴天」 | `play_song`（歌手+歌名一起说更准，会自动在线搜） |
| 「放周杰伦的歌」「来几首邓丽君」 | `play_artist`（本地+在线一起连播；说数量就播几首） |
| 「来点音乐」「随便放」「随机放 5 首」 | `random`（说了数量就只放几首） |
| 「随机播放在线音乐」「换一批」「来点没听过的」 | `random_online`（每次一批新的，默认 100 首） |
| 「放第 8 首」「列表里的第三首」 | `play_index` |
| 「库里有没有邓丽君」「有哪些歌手」 | `search` / `list`（只查不播） |
| 「暂停 / 继续 / 停止」「下一首 / 上一首」 | `pause` / `play` / `stop` / `next` / `prev` |
| 「音量调到 50」「声音大点」 | `volume`（0~100） |
| 「播放先锋898」「听 FM91.8」「第三个电台」 | `play_radio`；「所有电台都放一遍」→ `play_radio_all` |
| 「现在放的什么歌」 | `status` |
| 「收藏这首歌」「取消收藏」 | `fav_add` / `fav_del`（默认对当前在放这首） |
| 「播放我喜欢的歌」「播放收藏」 | `play_fav` |

### 8.2 灯光 `self.r1light.*`

| 语音示例 | 工具 |
|---|---|
| 「开氛围灯」「调成蓝色」「亮一点」「渐变快点」「关掉氛围灯」 | `ambient`（on/mode/luma/chroma/color） |
| 「开夜灯」「夜灯只开下面的灯」「夜灯调成暖橙色」「关掉夜灯」 | `night`（夜灯期间唤醒/播报灯全部停用，说「关掉夜灯」才恢复） |

### 8.3 闹钟 `self.r1alarm.*`

| 语音示例 | 工具 |
|---|---|
| 「每天早上七点叫我」「周一到周五七点半叫我」「明天七点叫我」 | `add`（默认随机播一首歌当铃；响铃音量独立，事后自动还原） |
| 「我有哪些闹钟」「明天几点叫我」 | `list` |
| 「把七点的闹钟关掉别响了」**（正在响时）** | `dismiss` —— 只关这一次，**明天照响** |
| 「把七点的闹钟停用」**（以后都不响）** | `toggle` |
| 「把七点的闹钟删了」 | `del` |
| 「闹钟声音太小」「闹钟音量调到 60」 | `vol` |

> 「关闭 / 停用 / 删除」三件事语义不同：**响铃中喊「关闭」= dismiss（这次别响）**；
> 「停用」= toggle（以后不响）；「删除」= del（彻底没了）。音箱会按语义处理，说的时候不必特意区分措辞。

## §9 常见问题速查

| 现象 | 处理 |
|---|---|
| 装完网页打不开 | 等 15~40 秒再刷（冷启动绑 8080 要几秒到几十秒），别急着断电 |
| 在线歌播不了 / 每 30 秒切一首 | 落雪没配或挂了：查 8100 音源页落雪地址 → `curl http://<NAS>:9527/api/music/search?name=x&limit=5` |
| 在线歌总在缓冲 | 8100 音源页把默认音质改回 `128k` |
| 收藏导入后又变 500 上限 | 升级到含 v1.3.259 的版本；设置里「本地曲目数量」设 0 = 不限 |
| 匹配出来名字不对 | 收藏页**长按歌名**重新匹配；或设置开「显示自定义歌曲名」只看自己的名字 |
| 匹配好的歌不显示匹配名 | 那是没播到那一首/没重新解析过；播到会更新，或长按手动绑 |
| WS 连不上（设置页 ws 显示红/空） | OTA 地址对不对 → 服务端起没起 → 激活码有没有绑 |
| 语音控制不了音乐 | 确认设置里「自定义音乐库」开关是开的；改过开关后重新唤醒一次让工具表生效 |
| TTS 和音乐都没声 | 公共音频出口堵了：对照版本 → 重启音箱 → 断电重启 |
| 重装后要重配什么 | OTA 地址（重装即清空）+ 重新激活；收藏/曲库索引不受影响（在 files/ 下） |

## §10 端口与进程备忘

| 端口 | 归属 | 说明 |
|---|---|---|
| **8080** | 音箱 player | Web 控制台，唯一对外入口，所有配置在这做 |
| 8100 | NAS MediaServer | 小智曲库（`/index.json` 一次吐全量） |
| 9527 | NAS lxserver | 落雪取链 + 管理后台 `/admin` |
| 8003 / 8000 | 小智服务端 | OTA / WS（自建时） |
