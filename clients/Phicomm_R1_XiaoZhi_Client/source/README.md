# Phicomm R1 专用小智 —— V2.0.5 发布说明

装机用的三个 apk 在 `apps/`；配套的 NAS 音乐服务端在 `R1XiaoZhi_MediaServer_v1.2.3/`；
安装脚本是 `一键安装.bat`（配 `adb.exe` 三件套）；**构建用的源码在 `源码/`**。

**对应关系**：

| 包 | 产物名 | 包内版本号 | 基线（测试序列） |
|---|---|---|---|
| device（小智本体，寄生在原厂 Pandora） | `XiaoZhi_Unisound_V2.0.5.apk` | `XzBootstrap.VERSION = 2.0.5` | `v1.3.329` |
| player（Web 控制台，寄生在原厂 EchoService） | `XiaoZhi_EchoService_V2.0.5.apk` | `Boot.VER = pl-2.0.5` | `pl-1.6.148` |
| so 宿主（Opus 编解码 so，无 root 只能由系统安装器解出） | `XiaoZhi_SoHost_V2.0.1.apk` | 沿用 V2.0.1 | — |

> 升级时**按 md5 判断**（`md5.txt`），不要只看版本号字符串。

## ★ 相比 V2.0.4 更新了什么

V2.0.4 的基线是 device `v1.3.256` + player `pl-1.6.95`；
V2.0.5 的基线是 device `v1.3.329` + player `pl-1.6.148`。

这一版的主线是**「有声书/节目」整条链路**（搜索、整本集表、我的节目、按书续播、
本地书库优先），另外修了录音链路的两个老问题，并把网页的「改了不生效」从根上去掉。

### 一、有声书 / 节目（本版主线）

V2.0.4 只能「点一集放一集」，这一版把它做成能长期听的一套。

| # | 能力 | 说明 |
|---|---|---|
| 1 | 节目搜索只列书名 | 不再一次把整本书几百集拉回来卡住界面；点书名弹窗选集，首行是「最近播放」，带集数搜索框 |
| 2 | 整本集表缓存 | 一本书枚举一次就记住（2 小时有效），第二次点开秒出；枚举转后台，**点的这一集先出声** |
| 3 | 我的节目 | 有声书收藏（和音乐收藏分开）：在播时点 ☆ 就收藏这本书，整批占位入列 |
| 4 | 播到才解析 | 队列里是 `/r/prog?aid=&ep=` 惰性地址，真正播到那一集才去取链；**解析不到就原地停，绝不把「非音频」丢给播放器** |
| 5 | 尾集自动续 | 一集播到队列末尾（回卷）会自动续拉下一批，不用回网页手动点 |
| 6 | 同名多版本 | 《凡人修仙传》在 NAS 上有 7 个版本，按主播 + 版本挑，不再盲挑到别人的版本 |

### 二、听书记忆（按书一张小表）

| # | 能力 | 说明 |
|---|---|---|
| 1 | 记到「集 + 秒」 | 每本书记「上次听到第几集、第几秒」（最多 8 本，LRU） |
| 2 | 语音续播接着播 | 说「继续听道诡异仙」会定位到那一集的那一秒；拖进度是在**新的一集真出声之后**才做，不会拖到上一集的秒数 |
| 3 | 换书不串 | 交叉听两本书时，不会拿 A 书的集号去续 B 书 |
| 4 | 没收藏也记 | 纯语音听的书（没进「我的节目」）也记进度，12 小时有效 |

### 三、下一集 / 上一集

| # | 变化 |
|---|---|
| 1 | 以 **player 真正在播的那一集**为基准恢复队列（不再用记忆里的集号），手动点、网页跳集之后都不会错位 |
| 2 | 队列快路径：当前行的下一行/上一行就是下一集 ⇒ 直接本地跳，不动队列、不重新拉列表 |
| 3 | 幂等护栏：目标集已经在队列里就不整批载回（避免重复入列、队列越滚越长） |
| 4 | 网页上播放有声书时，「下一首/上一首」按钮自动变成「下一集/上一集」，后台转发、立即返回，不卡界面 |

### 四、防误触（tail-kick 三道门）

以前「这一集刚播完」会被误判成「队列到底了」，于是自作主张续下一批、或者跳回另一本书。
现在要同时满足三条才允许回卷：

1. 30 秒内我们自己没往队列里推过东西（推过说明是用户手动点播，不是自然播完）；
2. 上一曲确实是当前队列的**最后一行**；
3. 书名能在「我的节目」里精确命中，且带着 albumId。

### 五、本地有声书库（NAS 上的 `/audiobook` 直接放）

| # | 变化 |
|---|---|
| 1 | 语音点播**本地优先**：先按书名问本地库（去掉书名号/标点/「有声小说」尾缀后再比对），命中就整批入列本地文件，**不走去在线取链** |
| 2 | 本地书的集号从 0 起（引子/序），起播定位按集号过滤，不会永远从引子开始 |
| 3 | 本地书排进播放队列时标题补「第N集 」，标题里**任意位置**已经有集号就不加（否则《凡人修仙传 第1234集》会变成两个集号） |
| 4 | 来源标签区分「📖 本地节目」与「在线节目」，网页一眼看出这一集是从 NAS 放的还是网上取的 |
| 5 | 本地书点播一次推 300 集入列（以前只推一页，听完一集就掉到队列外、串到别的书） |

### 六、录音链路（两个老 bug）

| # | 问题 | 修法 |
|---|---|---|
| 1 | 搭车模式（useUscTap）下 `record == null`，AEC 参考用的播放流没人挂 ⇒ 回声/自激、听着「半聋」 | 搭车模式下自动挂一条独立的常驻播放流作为 AEC 参考 |
| 2 | ALC 开着时固定增益其实**根本不参与运算**，界面上却还能点，用户以为「调了没反应 / 调坏了」 | ALC 与固定增益互斥：ALC 开着时增益段置灰不可点 |

### 七、网页控制台

| # | 变化 |
|---|---|
| 1 | 节目/书单三栏（搜索结果、节目列表、本地书）高度封顶 236px，书再多也在框内上下滑，不再把整张卡片撑长（按用户要求不显示外框，只留约束） |
| 2 | 铃声缓存清单同样封顶（以前缓存十几首就一路往下长） |
| 3 | 搜索框**删空立即回全列表**（在线、本地两栏都一样）：判断看「当前列表对应的词」，不看按钮状态；迟到的响应按词作废，不会把旧结果画回来 |
| 4 | 本地书列表缓存 + 扫盘指纹比对（NAS 那边扫盘时间没变就直接用缓存），同一本书第二次点开 0 延迟 |
| 5 | 页面不再被浏览器强缓存 10 分钟：`/` 改 `no-cache` + `ETag`（未变化回 304、0 字节）；顶部「页面已过时」横幅点一下会**先注销旧 Service Worker 再强刷**，不会只更新一半 |
| 6 | 歌单导入改成异步，按钮实时显示「导入中 X/N」，不再假死；大批量导入不再 O(N²) |
| 7 | 收藏列表可切「自定义原名 / 匹配名」；「没配上」的红标改成按失败次数（又失败一次就重新标红） |

### 八、NAS 服务端（v1.2.1 → v1.2.3）

| 版本 | 内容 |
|---|---|
| v1.2.1 | 读有声书目录自带的 sidecar（封面 / desc.txt / reader.txt / metadata.json）：作者、演播、年份、简介、每集时长 |
| v1.2.2 | 书列表封面改**绝对地址**（网页是从设备 IP 打开的，相对路径会打到设备上 ⇒ 封面全 404） |
| v1.2.3 | 修「容器偶发意外停止」：转发音频的超时原来卡整条流，播放器一暂停就 20 秒后被 abort，而那条流没人接 error ⇒ Node 进程退出。现在「等头 20s + 空闲 60s 看门狗」，流 error 全挂监听，另加进程级兜底 |

> 这一版的「本地有声书库」要用 v1.2.1 以上的服务端（`/api/abl/*`）。
> 老版本服务端仍能听在线书，但「本地书优先」用不了。

### 九、已知遗留（不影响日常使用）

| 项 | 说明 |
|---|---|
| 播放列表不持久 | 设备重启 / 重装任何一个包，播放进程一起重启 ⇒ 播放列表清空，重新点一次「导入播放列表并播放」即可 |
| 红标是内存态 | 「没配上」是 player 的会话内判定，player 重启后全部消失。**重启后不红了 ≠ 修好了** |
| 自动匹配仍可能配到翻唱 | NAS 搜索按热度排序，用**长按歌名 → 重链接**兜底 |
| 合集不自动挑部 | 本地《三体》是合集目录（含黑暗森林等子书），语音点播会落在合集本身，需要手动选具体那一部 |
| 书名号套娃 | 本地书的 name 自带书名号时，语音回话会出现「《《庆余年》有声小说》」（能播，只是文案难看） |
| 随机闹钟只吃在线池 | 断网时随机响铃可能放不出声（指定铃声有缓存，不受影响） |
| 长按 / 三击未接管 | 仍是原厂的 WiFi 配网 / 蓝牙配对 |

## 安装 / 升级

1. 音箱固件必须是 **3448**（脚本会校验，不是 3448 会锁住安装菜单）。
2. 音箱与电脑同一网络、已开 adb 网络调试。
3. 双击 `一键安装.bat`（用 CMD 或 PowerShell，**别用 Git Bash** —— 会吞引号），输入音箱 IP（如 `192.168.2.5:5555`）。
4. 菜单 `[1] 一键安装` 装三个包并拉起；从旧版升级同样走这条（覆盖安装，收藏、闹钟、我的节目与设置都保留）。
5. 浏览器打开 `http://<音箱IP>:8080/` → 顶部「激活」卡片取 6 位激活码 → 到小智服务端绑定。
6. 用自建服务器的，装完再用菜单 `[6]` 填一次服务器地址（重装会清空 OTA 地址）。

**升级提示**

- 装完 device 包，播放列表会清空（见「已知遗留」），收藏、闹钟、「我的节目」不受影响。
- 从 V2.0.4 及更早升级，浏览器里可能还压着旧页面（旧版给了 10 分钟强缓存）：
  等顶部「页面已过时」横幅出来点一下即可，或手动刷新一次。**这一版之后不会再有这个问题**。
- 本地有声书库要 NAS 端 ≥ v1.2.1：把 `R1XiaoZhi_MediaServer_v1.2.3/` 覆盖到 NAS 后
  `docker compose up -d --build`（详见该目录 README）。

## 源码

`源码/` 下是本版两个包的实际构建输入：

```
源码/
  README.md                     ← 目录说明 + 怎么重建
  device/                       ← 主包（寄生 Pandora）
    v2src/                      ← 本项目写的注入代码（Java）
    uni_smali/                  ← 原厂 smali 基线（已打好本项目的钩子）
    build_v205.sh               ← 日常测试线构建脚本（产出 1.3.x）
    build_rel_V205.sh           ← 本发布包的构建脚本（产出 2.0.5）
    _gen_rel_v205.py            ← 由 build_v205.sh 生成上面那份 release 脚本
    janus_poc.py                ← Janus(CVE-2017-13156) 拼包 + v1 签名校验
  player/                       ← 控制台包（寄生 EchoService）
    plsrc/                      ← 注入代码（Java）
    ui/                         ← 网页前端（player.html + gen_java.py）
    build_pv81.sh               ← 日常测试线构建脚本（产出 pl-1.6.x）
    build_rel_V205.sh           ← 本发布包的构建脚本（产出 pl-2.0.5）
    patch_*.py / _gen_assets.py ← smali 补丁与资源抽取脚本
```
