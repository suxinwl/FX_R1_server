# 构建环境准备（V2.0.5 源码包）

这个包里的源码**能独立构建**，但工具链不随包提供（JDK 300 MB+，Android SDK 有授权要求）。
按本文准备一次，约 20 分钟，之后 `bash build_rel_V205.sh` 就能出 apk。

> 只在 **Windows + Git Bash** 上验证过。Linux/macOS 脚本里做了兜底（`pwd -W` 失败会退回 `pwd`），
> 但没实测；`.exe` 后缀的探测逻辑两边都兼容。

---

## 1. 一句话总览

```
源码/
├─ tools/          ← 你要准备的东西全放这里（也可以放别处，用 R1_TOOLS 指过去）
│  ├─ jdk/             JDK 17（解压后根目录，下面有 bin/javac.exe）
│  ├─ android.jar      Android SDK 的 android.jar
│  ├─ r8.jar           Android SDK build-tools 里的 r8.jar
│  └─ smali/           smali/baksmali 2.5.2 + 6 个依赖 jar
├─ device/         设备端：v2src + uni_smali + ui + javacp + 原厂壳
├─ player/         播放器端：plsrc + smali_echo + smali_exo + 原厂壳
├─ build_check.sh  自检
└─ README.md       包结构说明
```

另外需要：**Python 3**（进 PATH 即可）、**Git Bash**（bash 环境，不能用 cmd/PowerShell）。
可选：node（页面 JS 语法自检）、7z（打压缩包）。

## 2. 逐项获取

### JDK 17

Adoptium Temurin 17 的 Windows x64 **zip** 版（不要 msi，zip 免安装）：

- 下载：<https://adoptium.net/temurin/releases/?version=17&os=windows&arch=x64&package=jdk>
- 解压后目录形如 `jdk-17.0.20.1+1/`，把**这一层**改名 `jdk` 放进 `源码/tools/`
- 验收：`源码/tools/jdk/bin/javac.exe -version` 打出 `javac 17.0.x`

已经装过 JDK 17 的话，也可以不放进 tools —— 脚本会读 `JAVA_HOME`，再不行就用 PATH 里的 `javac`。

### android.jar

来自 Android SDK Platform（脚本只用来当 `-bootclasspath`，API 21 以上都行）：

- 装了 Android Studio：`%LOCALAPPDATA%\Android\Sdk\platforms\android-33\android.jar`
- 只用命令行：装 [cmdline-tools](https://developer.android.com/studio#command-tools)，然后
  `sdkmanager "platforms;android-33"`
- 拷到 `源码/tools/android.jar`

### r8.jar

同一个 SDK，在 build-tools 里：

```
%LOCALAPPDATA%\Android\Sdk\build-tools\33.0.x\lib\r8.jar
```

拷到 `源码/tools/r8.jar`。没有 SDK 的话，Maven 坐标 `com.android.tools:r8`（挑个 3.x 版本）。

### smali / baksmali 2.5.2

**版本必须 2.5.2**，脚本里写死了 jar 名。两个渠道二选一：

- GitHub Release：<https://github.com/baksmali/smali/releases/tag/v2.5.2>
  → 拿 `smali-2.5.2.jar`、`baksmali-2.5.2.jar`
- Maven Central（脚本 `BCP`/`SCP` 里就是这 8 个坐标）：

  | 文件 | 坐标 |
  |---|---|
  | `smali-2.5.2.jar` | `com.android.tools.smali:smali:2.5.2` |
  | `baksmali-2.5.2.jar` | `com.android.tools.smali:baksmali:2.5.2` |
  | `dexlib2-2.5.2.jar` | `com.android.tools.smali:dexlib2:2.5.2` |
  | `util-2.5.2.jar` | `com.android.tools.smali:util:2.5.2` |
  | `guava-25.1-android.jar` | `com.google.guava:guava:25.1-android` |
  | `jcommander-1.72.jar` | `com.beust:jcommander:1.72` |
  | `commons-cli-1.4.jar` | `commons-cli:commons-cli:1.4` |
  | `antlr-runtime-3.5.2.jar` | `org.antlr:antlr-runtime:3.5.2` |

  全部放进 `源码/tools/smali/`，文件名照左列写（jar 名不对脚本找不到）。

### Python 3

<https://www.python.org/downloads/windows/> 安装时勾 **Add python.exe to PATH**。
脚本只用标准库（`io/os/re/struct/zipfile/subprocess/hashlib`），不需要 `pip install` 任何东西。

> 别用 Microsoft Store 那个 `python` 占位符，会弹商店。装完在 Git Bash 里
> `python -V` 能出版本号才算通。

## 3. 自检 → 构建

```bash
cd 源码
bash build_check.sh
```

全绿就可以构建：

```bash
cd 源码/device && bash build_rel_V205.sh     # -> XiaoZhi_Unisound_V2.0.5.apk（约 31 MB，3~5 分钟）
cd 源码/player && bash build_rel_V205.sh     # -> XiaoZhi_EchoService_V2.0.5.apk（约 6 MB，2~4 分钟）
```

工具链没放在 `源码/tools` 的话：

```bash
R1_TOOLS=/d/r1tools bash build_rel_V205.sh
```

构建脚本自己也会做一遍依赖自检，缺东西直接报清楚路径再退出，不会跑到一半才炸。

## 4. 会遇到的坑

| 现象 | 原因 / 处理 |
|---|---|
| `python.exe: can't open file '...ui\gen_java.py'` | `ui/` 缺文件，或没在 `device/` 目录下跑（脚本会自己 `cd`，一般不会） |
| `javac: file not found` 且路径是乱码 | 源码路径含中文。脚本已改用相对路径规避 GBK 问题，但**仍建议放在纯 ASCII 路径**下，如 `D:\r1src` |
| `aapt dump badging` 报 `Entry at offset zero` | 正常。这是 Janus 包（前置 dex + 原厂壳），aapt 读不了，不是坏包 |
| 构建到一半提示「覆盖已存在的文件」被杀 | 作者的机器有这层限制，脚本用 `_stale/` 先挪走再重建。你的机器没有就无感 |
| `bash: ... command not found` | 你在 cmd/PowerShell 里跑了。用 Git Bash |
| 页面改了但构建出来的还是旧页面 | `ui/ui.html` 改完不用手动跑生成器，脚本第 0.4 步会自动重生成 `UiModern.java`；若失败会直接 exit 1 |
| 构建产物版本号是 `1.3.x` 不是 `2.0.5` | 你跑的是 `build_v205.sh`（测试线）。要 2.0.5 请跑 `build_rel_V205.sh` |

## 5. 两条版本序列

| 序列 | 版本号 | 脚本 | 说明 |
|---|---|---|---|
| 测试线 | device `1.3.x` / player `pl-1.6.x` | `build_v205.sh` / `build_pv81.sh` | 日常迭代 |
| 发布线 | device `2.0.x` / player `pl-2.0.x` | `build_rel_V205.sh` | 出正式包用 |

`build_rel_V205.sh` 由 `_gen_rel_v205.py` 从测试线脚本生成，唯一区别是：javac 前把源码里的版本串
临时改成 `2.0.5` / `pl-2.0.5`，打包完立刻还原。所以**源码树永远停在测试线版本**，
两条序列不会串。要出下一个版本，改 `_gen_rel_v205.py` 里的版本串重跑即可。
